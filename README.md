# 个人服务入口页

一个纯静态的跳转页，托管在 GitHub Pages 上，用于在**纯 IPv4 网络**下也能打开一个入口，点进去访问本机的 IPv6 服务。

## 为什么需要它

本机所有服务只通过 IPv6 提供（`web.521096.xyz` 只有 AAAA、没有 A 记录）。`<user>.github.io` 同时有 A 和 AAAA 记录，所以在任何网络下都能打开，作为“门牌号”。

## 页面能力

- **本机入口卡片**：`http://web.521096.xyz:8180/` 是本机 nginx 的入口页，HTTP 直连，页面上有醒目的主按钮。
- **三步 IPv6 检测**：先请求 `api64.ipify.org`，返回地址含 `:` 即判定有 IPv6；否则再请求 `ipv6.icanhazip.com`，成功即判定有 IPv6；两者都失败则明确提示“探测服务不可达”，不误导。每次请求 4 秒超时，总耗时不超过 8 秒。
- **无 IPv6 时**：提示改用手机流量，并显示「复制本页地址」按钮（`navigator.clipboard`，失败时自动选中地址文本）。
- 所有入口统一使用域名 `web.521096.xyz`，页面不硬编码任何 IP 地址。

## 限制

- 只能跳转，不能反向代理或内嵌：GitHub Pages 是纯静态托管，没有服务端。
- 页面无法直接探测 `web.521096.xyz` 是否可达：本次入口是 HTTP，在 HTTPS 页面里会被浏览器按混合内容拦截，因此只能判断“本机网络是否有 IPv6”，再通过链接跳转。
- 8443 / 9943 / 9450 使用自制证书，首次访问浏览器会提示“连接不是私密连接”，选择继续前往即可。
- 8180 是 HTTP，不受自签证书影响。
- 访问者自己的网络没有 IPv6 时，本页能打开，但目标仍然打不开（页面会给出提示和复制按钮）。

## 维护

修改 `index.html` 或本文件后，通过 GitHub REST API 提交即可，Pages 会在 1 分钟内自动重新构建。
